## Project

Portal 2D — a desktop-only, keyboard-driven puzzle game: the player crosses grid-based test chambers using a pair of portals (Vite + Vue 3, TypeScript, Composition API with `<script setup>`, vue-router, ESLint + @stylistic + type-aware typescript-eslint via @vue/eslint-config-typescript). It is a static site on Firebase Hosting; there is no backend.

`TODO.md` holds the author's longer-term ideas (submitted chambers, ratings, a chamber database). They are not planned work; do not build any of it unless asked.

## Layout

```
src/
  main.ts, app.vue, router.ts     entry, desktop-only and loading gates, routes (/, /chamber/:number)
  assets/styles.css               design tokens and shared classes (.wall, .room, .menu-row, .button-*, .keycap, .ruled-label)
  assets/audio/                   music and sound effects, imported so Vite fingerprints them
  assets/images/                  the test-room photo behind the home screen (WebP), the test-subject figure on chamber rows, the Aperture Science logo on the loading screen (SVG, small enough that Vite inlines it)
  chambers/chamber_N.json         chamber layouts (format: docs/elements.md)
  components/screens/             loading_screen (first screen of every visit), home_screen (the menu, in up to three columns), chamber_screen
  components/                     the home menu's chamber row, settings switch (both menu rows), chamber map (its third column, shown for Play), link row (a page in About's third column, opened in a new tab) and changelog list, legend, dialogs (dialog_frame is the shared shell), logo, desktop-only notice
  game/                           the game itself: rules, renderer, input, sounds, music. Plain TypeScript
  services/                       chamber catalogue, changelog (releases shown under About), settings (sound/music), progress (completed chambers), last chamber (opened this visit, in memory), device detection, asset preloader
docs/elements.md                  what each chamber element does
public/                           favicon only
```

## Rules

- **After completing code changes**: Run `npm run lint:fix` and fix remaining errors, run `npm run build` (type-checks first) and fix any failures, then run `/delta-review` before responding.
- **Game/Vue boundary**: `src/game/` is plain TypeScript and never imports Vue, vue-router, `src/components/`, `src/services/` or `src/chambers/` (enforced in `eslint.config.js`). Screens drive it, not the other way around: `chamber_screen.vue` creates a `Level` on its canvas, calls `load` (also used for reset), `resize`, `dispose`, toggles `paused`, and gets `onCompleted` back. Services may import from `src/game/` (settings flips `Sound.enabled` and switches between `menuMusic`, played on the home screen, and `gameMusic`, played in a chamber; the asset preloader hands each audio player its downloaded file through `useAudioFile` in `audio_sources.ts`). `Sound.MENU_BUTTON` and `Sound.START` are interface sounds the game never plays: components play the first on the loading screen's Start button, on dialog buttons, on every move of the home menu's highlight (keys, Tab or pointer), on opening and closing a home menu section, on stepping into and back from About's third column (not on opening Feedback or a page, which leave the game), on settings switches (after the change, so turning sound effects off stays silent) and on opening the pause menu or the reset progress confirmation, and the second when a chamber is started from the home menu. They obey the sound effects setting like every other `Sound`. Game objects are never made reactive and per-frame data never passes through a `ref`.
- **Game behaviour is frozen**: The game was translated line by line from the original JavaScript, keeping its rules, update order, sounds and drawing exactly. Do not change rules, drawing, colours or sizes unless explicitly asked. Its colours are hex literals inside `src/game/`; leave them until the chamber visuals are reworked.
- **Keyboard ownership**: The game's `Input` owns the arrows, A, D, Space and Ctrl, and calls `preventDefault` on arrows and Space only while playing. Screens own Escape. On the home screen, which has no game running, Up and Down move the highlight within the column that has the keyboard (wrapping around; in the first column they change nothing else), Right or Enter opens the highlighted section and steps into it, Left or Escape closes it again. Under About the third column follows the highlighted row (a list of pages, or the changelog); Right, Enter or a click steps into the pages or the changelog (where Up and Down scroll it), and Left or Escape steps back to the About row. Arrows with Alt, Ctrl or Meta are left to the browser. Each column is one Tab stop (its highlighted row, or the changelog), and a held (repeating) Enter is ignored so it can't carry over from the previous screen. The first arrival shows only the sections, with Play highlighted and focused but not open; back from a chamber, Play is open with that chamber highlighted and focused. Hovering a row highlights it, in any column; clicking a section opens it like Enter. While any dialog is open the game is paused and its input is ignored (on the home screen, the menu ignores every key but Escape, which closes the dialog), and the dialog's buttons get the keyboard (`dialog_frame.vue`: first action focused, arrow keys and Tab move between actions). The loading screen's Start button takes focus once loading finishes.
- **Desktop only**: Touch-first devices (`pointer: coarse`) get the desktop-only notice instead of the app. Do not add mobile layouts or touch controls.
- **Chambers**: A chamber is a JSON file in `src/chambers/` plus an entry (its number) in `src/services/chamber_catalogue.ts`. `ChamberData` (`src/game/chamber_data.ts`) must accept the JSON import without a cast, so the type checker validates every chamber file.
- **Persistence**: `localStorage` keys are prefixed `portal-2d.` and every access is wrapped in `try`/`catch` (storage can be blocked). Stored: sound on/off, music on/off, completed chambers (cleared by Reset progress under Settings). The last chamber opened (which the home menu highlights on the way back) is kept in memory only.
- **Assets**: Import assets from `src/assets/` so Vite fingerprints them; nothing new goes in `public/`. Fonts come from Google Fonts via `<link>` in `index.html`.
- **Loading screen**: Every visit (desktop only) opens on `loading_screen.vue`, which downloads every file under `src/assets/audio/` and `src/assets/images/` (`asset_preloader.ts` finds them at build time), then waits for Start. Images are read back from the browser cache. Audio is handed to the game's players as an in-memory copy, because Firebase varies responses by encoding and a media request would miss the cache and download the file again; the players (created through `createAudioPlayer`) download nothing on their own until they first play. Pressing Start plays the menu click, then the requested address opens, and the press lets the music play. In development (`npm run dev`) the bar takes at least 0.5 s, so the loading state can be seen. Delete asset files that are no longer used, since they are downloaded too. The preloader's font list must match the faces requested in `index.html`. A file that fails is skipped and loads on demand later.
- **No test suite**: This project has no tests by design. TypeScript and the type-aware lint rules are the safety net — do not weaken `strict` or `noUncheckedIndexedAccess`, and do not add `any` to silence an error.
- **TypeScript projects**: `tsconfig.json` only references `tsconfig.app.json` (browser, `src/`, extends `@vue/tsconfig/tsconfig.dom.json`) and `tsconfig.node.json` (`vite.config.ts`, extends `@tsconfig/node24`). An option the two bases don't already cover must be set in both.
- **Deploy**: `npm run deploy` builds into `dist/` (git-ignored) and runs `firebase deploy --only hosting` (project `portal-2d`). `firebase.json` rewrites every path to `/index.html` for history-mode routing.
- **Doc maintenance**: After changes, check whether `AGENTS.md` and `docs/elements.md` need updating.

## TypeScript

- No semicolons. Single quotes. One class per file. Named exports.
- Files `snake_case`; classes, interfaces and type aliases `PascalCase`; functions and variables `camelCase`.
- Full descriptive names — no `el`, `p`, `btn`. Allowed short names: `i`, `j` (loop counters), `x`, `y` (coordinates), `dx`, `dy` (deltas), `ctx` (canvas context).
- Always import with the `@` alias (mapped to `src/`). No relative paths, no file extensions. `import type` for type-only imports.
- No object shorthand: write `{level: level}`, not `{level}` (enforced). Objects and arrays with two or more items go one per line (enforced).
- No TypeScript `enum`: use string-literal unions, with a const object when named values help.
- Indexing a `Record` or array yields `T | undefined`: handle the miss rather than asserting it away with `!`.
- Prefer getters over methods for parameterless functions that only read state.
- Unused parameters: `_`, `__`, `___`.
- Comments: a JSDoc block on every class and function (no types — TypeScript declares them), an end-of-line comment on each field's first declaration, plain comments above non-obvious logic.

## UI

- Always use the `frontend-design` skill when changing the UI.
- Direction: test-facility signage. Cool light panels on a seamed wall (the home screen sits on a photo of a test room instead, via `.room` and `.room-inner`, which keep its content on the room's back wall, clear of the side walls and floor, with the wordmark above the menu; the chamber screen puts the game on the same photo, blurred so the eye stays on the chamber, beside a light rail holding the wordmark, the chamber sign (a spaced label and rule over the two-digit number) and the controls legend (keycaps, then a divider, blue or orange for the portal keys, before what each key does); the loading screen sits on the seamed wall with larger panels, rivets where the seams cross and a soft vignette, under the Aperture Science logo, muted), the home menu as lettering straight on the room's wall, with no panel (Play, Settings and About; once a section is opened, its rows in sign capitals beside them, the first level with the section's own row (a cascade, from the shared `--menu-row-height`), for Play the highlighted chamber's map, and for About, level with the highlighted row, the pages as rows ending with an arrow leaving a box (they open a new tab), or the changelog beside a thin rule that darkens when it has the keyboard; the row with the keyboard sits on a see-through dark bar with white lettering, which is also its focus mark, and the chosen row of a column without the keyboard on a fainter one; a chamber row ends with the test-subject figure, grey until the chamber is completed and green after; Settings ends with Reset progress, a plain row that leaves the red to its confirmation dialog), thin rules, chamber numbers as large sign numerals, and the game's own colours as the only accents: blue marks interaction and success (the pause dialog's band and Continue button, the chamber-complete dialog), orange is the second portal (the wordmark and the legend), the floor button's red marks caution (actions that discard progress: the confirmation dialog's band and button), and the test subject's green marks a completed chamber on its row. Keep these meanings consistent.
- Tokens live on `:root` in `src/assets/styles.css` (`--color-wall`, `--color-panel`, `--color-rule`, `--color-white`, `--color-ink`, `--color-ink-muted`, `--color-blue`, `--color-blue-deep`, `--color-orange`, `--color-red`, `--color-red-deep`, `--color-subject`, `--color-chamber`, plus `-rgb` triplets for alpha). Use tokens, not new colours.
- Type: `Barlow Condensed` for display (wordmark, sign numerals, titles), `Barlow` for everything else.
- CSS colours are always `rgba()`, never hex (the game's canvas colours are the exception, see above). `border-radius` in `rem` (exception: `50%` for circles).
- Repeated CSS goes to `src/assets/styles.css`; component-specific styles stay in scoped `<style>` blocks.
- Accessibility floor: visible keyboard focus, keyboard-operable dialogs and switches, and `prefers-reduced-motion` respected (global rule in `styles.css`).
- Copy is sentence case, plain verbs; a button says what it does ("Reset chamber", not "OK"). Signage labels may be shown in capitals with `text-transform`; the text itself stays sentence case.
- CSS comments: `/* ==== */` block dividers for major sections, a short phrase above a rule for its purpose.
